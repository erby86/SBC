# ADR-0020: ทำหน้าจัดการทะเบียน (M21) ก่อนฉาก 3D

- **สถานะ:** Accepted
- **วันที่:** 2026-10-03

## บริบท

แผน (modules-by-gate-v2, kickoff-plan-v2) วาง M21 หน้าจัดการทะเบียนไว้หลัง M18–M20 และให้ใช้ Adminer แก้ข้อมูลไปก่อน แต่ ณ วันที่ 3 ต.ค. งานโค้ด G1–G3 เสร็จเร็วกว่าแผนมาก สิ่งที่ค้างคือข้อมูล: AP 46 ตัวยังไม่รู้ชั้น, IP/uplink ของอุปกรณ์บางตัว, ลำดับห้อง ผู้ใช้ (STF-01) ต้องการแก้ข้อมูลเหล่านี้ในหลังบ้านเอง แทนการรองานหน้างานหรือแก้ชื่อในแต่ละ controller และไม่ต้องการแก้ตารางตรงด้วย Adminer

## การตัดสินใจ

- ลำดับใหม่ของ G4: **M18 → M21 → M19 → M20 → M22**; M17 (deploy prod) ทำหลัง M20 ก่อนเปิด `noc.sbc.lan`
- dependency ตามแผนยังครบ: M21 ขึ้นกับ M14 (เสร็จ) และ M18 (ทำก่อน)
- M21 เพิ่มงาน: เลือกชั้น/ห้องให้ AP จากรายการ `unplaced_ap` ได้โดยตรง (จับคู่ด้วย MAC; งานนำเข้าไม่ย้ายตำแหน่งที่คนกำหนด — M06)
- ระหว่างยังไม่มีการเข้าสู่ระบบ (M23): หน้าแก้ไขเปิดเฉพาะ dev (`noc-dev.sbc.lan`, access list วง management) ทุกการแก้บันทึกใน `audit.change_log` ด้วย actor ที่ระบุตัว; **prod เปิดหน้าแก้ไขได้หลัง M23 เท่านั้น**
- ไม่เปลี่ยน schema; การแก้ใช้ `row_version` กันแก้ทับตาม M21 เดิม

## ผลที่ตามมา

- ผู้ใช้แก้ทะเบียนบนเว็บได้ก่อนมีภาพ 3D และข้อมูลพร้อมขึ้นเมื่อถึง M19
- เส้นทางวิกฤตไม่ยาวขึ้น (M21 ขนาด L ย้ายมาก่อน M19 ซึ่งต้องรอข้อมูลอยู่แล้ว)
- ความเสี่ยง: หน้าแก้ไขบน dev ไม่มีล็อกอินช่วงหนึ่ง — จำกัดด้วยวงเครือข่าย + บันทึกการแก้ และไม่เปิดบน prod จนกว่า M23 เสร็จ
