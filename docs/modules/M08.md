# M08 — ส่ง tag ไป Zabbix + จับคู่ host

ตาม modules-by-gate-v2: งานจับคู่ host (IP/ชื่อ) → `external_refs`; เขียน tag `building` `floor` `loc` `role` `uplink`; host ที่ไม่มีในทะเบียนเข้า "ไม่มีตำแหน่ง"

**เสร็จเมื่อ:** host เครือข่ายใน Zabbix มี tag ครบ 100%; รันซ้ำไม่เกิดการเปลี่ยนแปลงถ้าข้อมูลเท่าเดิม

## ส่วนที่ 1: จับคู่ host (อ่านอย่างเดียว) — ทำแล้ว

| ไฟล์                                   | หน้าที่                                                                                        |
| -------------------------------------- | ---------------------------------------------------------------------------------------------- |
| `apps/worker/src/connectors/zabbix.ts` | client JSON-RPC ของ Zabbix 7.0 (token แบบ Bearer, timeout 15 วินาที) — ตอนนี้ใช้แค่ `host.get` |
| `apps/worker/src/jobs/zabbix-match.ts` | งาน `zabbix-match` ทุก 15 นาที (system `zabbix`)                                               |

กติกาการจับคู่ (`matchHosts`, ทดสอบแยก):

1. IP ของ interface ใน Zabbix = `net.devices.mgmt_ip` → จับคู่ (by `ip`)
2. ไม่ตรง IP → ชื่อ host ใน Zabbix = `net.devices.hostname` (ไม่สนตัวพิมพ์) → จับคู่ (by `hostname`)
3. ตรงหลายอุปกรณ์ หรืออุปกรณ์ถูก host อื่นจับไปแล้ว → `sync.issues` kind `ip_conflict` (ไม่จับคู่)
4. ไม่ตรงอะไรเลย → `sync.issues` kind `unmatched_host` (= รายการ "ไม่มีตำแหน่ง")

- ผลเก็บใน `core.external_refs` (`entity_table = 'net.devices'`, `system_code = 'zabbix'`, `external_id` = hostid, `external_key` = ชื่อ host) — M07 `not_in_zabbix` อ่านจากที่นี่
- issue เปิดครั้งเดียวต่อ host (ไม่ซ้ำทุกรอบ) และปิดเอง (`resolved_at`) เมื่อ host นั้นจับคู่ได้แล้ว
- เขียนในฐานด้วย actor `worker:zabbix-match`
- worker รับ `ZABBIX_URL` + `ZABBIX_TOKEN_READ` จาก `dev.env` (เฉพาะ worker ไม่ส่งให้ api); ไม่ตั้งค่า → งานนี้ถูกปิดพร้อมคำเตือนใน log

ผลทดสอบ (ฐานจริง + Zabbix จำลองตาม 8 host จริง): จับคู่ 5 (c2116, c1036, mainA, mainB, m-i2), unmatched 3 (.15, .152, .157), `not_in_zabbix` ลดลง 5; รอบสองไม่เปิด issue ซ้ำ; เติม IP ให้ m-b1 → รอบถัดไปจับคู่และปิด issue เอง

**บน dev (2026-10-02):** `{zabbix_hosts: 8, matched: 5, matched_by_ip: 5, unmatched_hosts: 3}`; issue เปิด 3: Main8M (.152), Bldg1 (.157), BldgICET1 (.15)

- ค้าง: ผู้ใช้จะไล่ตรวจ IP จริงก่อนเติมในทะเบียน (คาดว่า .152 = `m-s8`, .157 = `m-b1`, .15 = `m-i1` แต่ยังไม่ยืนยัน; รุ่นในทะเบียน SG2428P ขัดกับชื่อ host SG3428)

## ส่วนที่ 2: เขียน tag (ADR-0019) — โค้ดเสร็จ รอตั้งค่าใน Zabbix

| ไฟล์                                   | หน้าที่                                                                                                                                   |
| -------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `apps/worker/src/connectors/zabbix.ts` | เพิ่ม `hostsWithTags(groups)` และ `setHostTags()` (`host.update`)                                                                         |
| `apps/worker/src/jobs/zabbix-tags.ts`  | งาน `zabbix-tags` ทุก 15 นาที: จับคู่ host ที่ token เห็น (กติกาเดียวกับส่วน 1) แล้วเขียน `building` `floor` `loc` `role` `uplink` จากฐาน |

- คง tag ที่ NOC ไม่ได้ดูแลไว้; tag ที่ไม่มีค่า (เช่น ไม่มี LOC) ไม่เขียน
- เขียนเฉพาะเมื่อค่าต่าง → รันซ้ำไม่เปลี่ยนอะไร (เงื่อนไขเสร็จข้อ 2)
- worker ใช้ `ZABBIX_TOKEN_SYNC` + `ZABBIX_TAG_GROUPS` (ค่าเริ่ม `99-NOC-Test`); ไม่มี token → งานถูกปิด
- ทดสอบ: Zabbix ในหน่วยความจำ + ฐานจริง — เขียน 2 host, host ไม่รู้จัก 1, รอบสองเขียน 0, tag `vendor` เดิมยังอยู่

**บน dev (2026-10-03):** ตั้ง `99-NOC-Test` + host `NOC-Test-CCR1036` (IP 192.168.1.2, ปิดเฝ้าระวัง) + ผู้ใช้ `noc-api-sync` (role Admin, RW เฉพาะ `99-NOC-Test`) — token sync เห็นแค่ host ทดสอบ, `host.update` บน host จริงถูกปฏิเสธ; งาน `zabbix-tags` เขียน `building=b2 floor=1 loc=LOC-187 role=core uplink=c2116` (ค่า c1036 จากทะเบียน) ✅

**สถานะเงื่อนไขเสร็จ:** การเขียน tag + รันซ้ำไม่เปลี่ยน (CI) พิสูจน์แล้ว; "host เครือข่ายใน Zabbix มี tag ครบ 100%" บน host จริงทำใน M17 (token prod) ตาม ADR-0013/0019
