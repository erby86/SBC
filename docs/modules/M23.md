# M23 — เข้าสู่ระบบ + บทบาท

ตาม modules-by-gate-v2 (แก้ตาม ADR-0023): บัญชีในเครื่องแทน Google OIDC, CLI สร้าง/ตั้งรหัส/ปิดบัญชี, argon2id, session Redis 12 ชม., กันเดารหัส, บทบาท operator/admin, เลิกใช้ `REGISTRY_EDIT`

**เสร็จเมื่อ:** ผู้ไม่มีสิทธิ์เข้าหน้าจัดการ/รับเรื่องไม่ได้; จอทีวีเปิดได้โดยไม่ล็อกอิน

**สถานะ:** เสร็จ 2026-10-06 (ผู้ใช้ยืนยันบน dev) — edit API 401 เมื่อไม่ล็อกอิน, session `null`, layout 200 ไม่ต้องล็อกอิน; หน้าแรก/ทีวีเปิดได้, ล็อกอินผิด/ถูก, แก้ทะเบียนด้วย admin, operator ไม่มีสิทธิ์, audit ครบ; dev ยังใช้ `SESSION_COOKIE_SECURE=false` จนกว่าจะทำ `internal-ca.md`

## การตัดสินใจในโมดูลนี้

- **ดูไม่ต้องล็อกอิน:** GET ทั้งหมดเดิม (ผัง สถานะ ค้นหา ทีวี `/api/status/ws`) ไม่เปลี่ยน — จำกัดด้วย access list `sbc-noc-mgmt` ตามเดิม
- **`/api/registry/edit/*` ต้องมี session บทบาท `admin`** (รวม GET) — ไม่มี session = 401, operator = 403; ผู้แก้ในประวัติเป็น `web:<รหัสพนักงานหรืออีเมล>@<IP>` จาก session แทน header `X-Noc-Editor`
- **รหัสผ่าน:** `node:crypto` argon2id (Node 24.7+, ไม่ต้องมี native module) m=19 MiB t=2 p=1 เก็บแบบ PHC; อีเมลที่ไม่มีอยู่ก็ verify กับ hash หลอกเพื่อให้ใช้เวลาเท่ากัน
- **session:** id สุ่ม 32 ไบต์ใน cookie `noc_session` (HttpOnly, SameSite=Strict, Secure) — Redis เก็บเฉพาะ SHA-256 ของ id (`<prefix>session:<sha256>`) อายุ 12 ชม. ไม่ต่ออายุ; ทุกคำขอที่ต้องมีสิทธิ์อ่านบัญชีจากฐานใหม่ ปิดบัญชีแล้วมีผลคำขอถัดไปทันที (ไม่ต้องลบ session ใน Redis)
- **กันเดารหัส:** ผิด 5 ครั้งต่อ IP + อีเมล ล็อก 15 นาที (`<prefix>login:fail:<sha256>`)
- **กัน CSRF:** cookie SameSite=Strict + คำขอเขียนที่มี `Origin` คนละ host หรือ `Sec-Fetch-Site: cross-site` ได้ 403
- **https:** `SESSION_COOKIE_SECURE=true` (ค่าตั้งต้น) = cookie Secure และล็อกอินได้เฉพาะเมื่อ `X-Forwarded-Proto: https`; web nginx ส่งค่าจาก NPM ต่อ (`$noc_forwarded_proto`); prod ตั้ง `true` ตายตัว; dev ตั้ง `false` ใน `dev.env` ได้เฉพาะก่อนทำ `docs/runbooks/internal-ca.md`
- **ฐานข้อมูล:** migration `0003_local_accounts` เพิ่ม `auth.users.password_hash`, `password_changed_at`, CHECK อีเมลตัวเล็ก (NOT VALID); **ไม่ใส่ audit trigger บน `auth.users`** เพราะ change_log จะคัด hash ไปด้วย — เหตุการณ์บัญชี (สร้าง ตั้งรหัส บทบาท ปิด/เปิด ล็อกอิน ล็อกอินผิด ออก) ลง `audit.user_actions` แทน
- **ไม่ทำในโมดูลนี้:** ค่าส่วนตัวผู้ใช้ (`auth.user_prefs`) — ค่าโหมดประหยัด/ธีม/ผ่านการแนะนำยังอยู่ใน localStorage ของแต่ละเครื่อง เพราะการดูไม่ต้องล็อกอิน; TOTP (ADR-0023 ข้อ 3); หน้าเปลี่ยนรหัสบนเว็บ (ใช้ CLI)

## ขั้นตอนบน dev

### 1. ดึงงาน + PR + อัปเดต dev

ตาม `docs/runbooks/github-to-gitea.md` ข้อ 1–3 (branch `module/M23-login`) — `deploy.sh staging` รัน migration `0003` ให้เอง

### 2. ให้ dev ล็อกอินผ่าน http ได้ชั่วคราว (ข้ามข้อนี้ถ้าทำ `internal-ca.md` เสร็จแล้ว)

```bash
grep -q '^SESSION_COOKIE_SECURE=' /opt/sbc-noc/dev.env || echo 'SESSION_COOKIE_SECURE=false' >> /opt/sbc-noc/dev.env
cd /opt/sbc-noc/src && infra/scripts/deploy.sh staging 2>&1 | tail -3
```

ควรจบด้วย `staging OK`; log api มีคำเตือน `SESSION_COOKIE_SECURE=false: login over http` — ลบบรรทัดนี้ออกเมื่อ dev ใช้ https แล้ว

### 3. สร้างบัญชี

```bash
NOC_EMAIL=you@sb-school.ac.th   # แก้เป็นอีเมลจริงก่อนรัน (ห้ามใส่ < >: bash ถือเป็นการอ่านไฟล์)
docker exec sbc-noc-dev-api node dist/user-cli.js add "$NOC_EMAIL" admin
docker exec sbc-noc-dev-api node dist/user-cli.js add noc-op-test@sbc.lan operator
docker exec sbc-noc-dev-api node dist/user-cli.js list
```

ควรเห็น `created …` + `password: …` (แสดงครั้งเดียว — เก็บลงที่เก็บรหัสผ่าน) และ `list` 2 บรรทัด; ถ้าใน `core.staff` มีรหัสพนักงานแล้ว เติม `--staff STF-01` ตอน `add` เพื่อให้ประวัติแสดงรหัสแทนอีเมล; ตั้งรหัสเองแทนรหัสสุ่ม: `read -rs P && printf '%s\n' "$P" | docker exec -i sbc-noc-dev-api node dist/user-cli.js passwd "$NOC_EMAIL" --stdin; unset P`

### 4. ตรวจเงื่อนไขเสร็จ

```bash
curl -s -o /dev/null -w '%{http_code}\n' http://noc-dev.sbc.lan/api/registry/edit/options
curl -s http://noc-dev.sbc.lan/api/auth/session; echo
curl -s -o /dev/null -w '%{http_code}\n' http://noc-dev.sbc.lan/api/registry/layout
```

ควรเห็น `401`, `{"user":null}`, `200`

ในเบราว์เซอร์:

1. `http://noc-dev.sbc.lan/` และ `/?tv` เปิดได้โดยไม่ล็อกอิน ภาพและสถานะสดเหมือนเดิม
2. `/admin` ขึ้นฟอร์ม "เข้าสู่ระบบเพื่อจัดการ" → ใส่รหัสผิด ได้ "อีเมลหรือรหัสผ่านไม่ถูกต้อง"
3. ล็อกอินด้วยบัญชี admin → เห็นเมนูอุปกรณ์/ห้อง/AP รอตำแหน่ง และชื่อบัญชีมุมบน → แก้ชื่ออุปกรณ์สักตัวแล้วแก้กลับ → ประวัติแสดง `web:<อีเมล>@192.168.1.x`
4. ออกจากระบบ → ล็อกอินด้วย `noc-op-test@sbc.lan` → ได้ "ไม่มีสิทธิ์จัดการทะเบียน"
5. ปิดบัญชีทดสอบ: `docker exec sbc-noc-dev-api node dist/user-cli.js disable noc-op-test@sbc.lan`

บันทึกการเข้าใช้:

```bash
docker exec sbc-noc-dev-db psql -U sbc_noc -d sbc_noc -c "SELECT at, action, target, host(source_ip) ip, detail FROM audit.user_actions ORDER BY id DESC LIMIT 10"
```

ควรเห็น `login`, `login_fail`, `logout`, `account_create`, `account_disable`

## prod (หลัง dev ผ่าน)

1. ทำ `docs/runbooks/internal-ca.md` ให้ครบ (https บน `noc.sbc.lan`) — **prod ล็อกอินผ่าน http ไม่ได้** (ได้ "เข้าสู่ระบบได้เฉพาะทาง https")
2. `infra/scripts/deploy.sh prod` → สร้างบัญชีด้วย `docker exec sbc-noc-api node dist/user-cli.js add …`
3. หน้าแก้ทะเบียนบน prod เปิดหลังล็อกอิน (ADR-0020 ส่วน "prod เปิดหน้าแก้ไขได้หลัง M23")
