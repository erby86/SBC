# M03 — ฐานข้อมูล (schema v1.1)

## หน้าที่

สร้างฐานข้อมูล `sbc_noc` ตาม sbc-noc-schema-v1.1.sql และการตัดสินใจใน sbc-noc-schema-design-v1.2 พร้อมระบบ migration และการทดสอบกับ PostgreSQL 16 จริง

## สิ่งที่สร้าง

- `packages/db/migrations/0001_schema_v1_1.sql` — DDL v1.1 ตามต้นฉบับ: 9 schema, 61 ตาราง, view `api.*` 5 ตัว, trigger `touch_row` (row_version) และ `audit.log_change`, ค่าตั้งต้น lookup
- `packages/db/migrations/0002_roles.sql` — role `noc_migrate`, `noc_app`, `noc_read` (NOLOGIN) และสิทธิ์ตามหัวข้อ "สิทธิ์" ของ DDL
- `packages/db/src/migrate.ts`, `migrate-cli.ts` — ตัวรัน migration (advisory lock, checksum, ทีละไฟล์ใน transaction)
- `packages/shared` — `outletCodeSchema`, `rackCodeSchema`, `cableCodeSchema`, `locCodeSchema` ตาม ADR-0006 / ADR-0001
- dev stack: เปลี่ยนเป็น `postgres:16-alpine`, เพิ่ม container `sbc-noc-dev-migrate` รันก่อน api/worker
- CI: job `db-integration` ใน `build.yml` (PR เข้า main) ทดสอบกับ PostgreSQL 16 จริง
- ADR-0018 และแก้ ADR-0006 ให้ตรงกับ design v1.2

## วิธีรันในเครื่อง

```bash
pnpm --filter @sbc-noc/db build
DATABASE_URL=postgres://user:pass@localhost:5432/sbc_noc pnpm --filter @sbc-noc/db migrate
```

## วิธีทดสอบ

```bash
pnpm --filter @sbc-noc/db test                                     # unit (ไม่ต้องมีฐาน)
TEST_DATABASE_URL=postgres://.../ฐานว่าง pnpm --filter @sbc-noc/db test   # + schema บนฐานจริง
```

การทดสอบบนฐานจริงตรวจ: 61 ตาราง + 5 view, รันซ้ำไม่ apply ซ้ำ, `next_loc_code()` เริ่ม LOC-188, `row_version` เพิ่มและ `audit.change_log` บันทึก INSERT/UPDATE, lookup 17 บทบาท, role ทั้งสามเป็น NOLOGIN

บน sbc-ubuntu หลัง `up -d --build`:

```bash
docker logs sbc-noc-dev-migrate          # migrations done: applied 2 ...
docker exec sbc-noc-dev-db psql -U sbc_noc -d sbc_noc -c "SELECT version, applied_at FROM schema_migrations"
```

## ข้อจำกัด

- ยังไม่มีข้อมูลจริง (อาคาร ห้อง LOC-187 อุปกรณ์) — นำเข้าในโมดูลซิงก์/นำเข้าข้อมูล
- dev ยังใช้ superuser ของ container (`sbc_noc`); การใช้ `noc_app` / `noc_read` แบบ LOGIN ทำใน M17 พร้อม secret
- นโยบายเก็บข้อมูล (ลบ change_log เกิน 3 ปี ฯลฯ) เป็นงานตั้งเวลาของ worker ในโมดูลถัดไป
- dev เปลี่ยนจาก PostgreSQL 18 (M02) เป็น 16 ใช้ volume ใหม่ `sbc-noc-dev-db16-data`; volume เดิม `sbc-noc-dev-db-data` (ว่าง) ลบได้
