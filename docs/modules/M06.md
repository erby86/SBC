# M06 — นำเข้า AP จาก controller

ตาม modules-by-gate-v2: ตัวเชื่อม UniFi, Omada, LINK (อ่าน) → `net.devices` role ap + `managed_by` + `external_refs` (MAC)

**เสร็จเมื่อ:** AP 132 ตัวอยู่ในฐาน; AP ที่ยังไม่ระบุห้อง/ชั้นขึ้นรายการให้คนเติม

## ส่วนที่ 1: UniFi — โค้ดเสร็จ

controller: UniFi OS Server 5.1.42 (Network 10.6.106) บน Ubuntu `https://172.16.0.30:11443`, site ภายใน `02gt1bcf` (ชื่อแสดง SB-SCHOOL; site `default` ว่าง)
ผู้ใช้ `View Only` แบบ local (role `readonly`) — ไม่มีเมนู API key ในรุ่นนี้ จึงใช้ username/password

| ไฟล์                                  | หน้าที่                                                                                     |
| ------------------------------------- | ------------------------------------------------------------------------------------------- |
| `apps/worker/src/connectors/unifi.ts` | login `/api/auth/login` (cookie `TOKEN`) แล้วอ่าน `/proxy/network/api/s/<site>/stat/device` |
| `apps/worker/src/jobs/unifi-aps.ts`   | งาน `unifi-aps` ทุกชั่วโมง (system `unifi`, actor `worker:unifi-aps`)                       |

กติกา:

- เอาเฉพาะ `type = uap`; อาคาร/ชั้นอ่านจากชื่อ (`NAME_RULES`): `8SFL<ชั้น>-<n>` → s8, `A<ชั้น>-<n>` / `AF<ชั้น>-<n>` → ba, `BFL<ชั้น>-<n>` / `BF<ชั้น>-<n>` → bb
- AP ใหม่ → `net.devices` code `ap-<อาคาร>-<ชั้น>-<n>` (ชนกับ code เดิม รวมที่ลบแล้ว → ต่อท้าย MAC 4 ตัว), `floor_id`, `poe_powered`, model จาก `catalog.models` (สร้างให้ถ้าไม่มี), `managed_by` = `ctl-unifi`
- controller เองเป็นอุปกรณ์ `ctl-unifi` (role controller) สร้างครั้งแรกที่รัน
- จับคู่ของเดิมด้วย MAC (`external_refs` system `unifi`, `external_id` = MAC, `external_key` = ชื่อใน UniFi) แล้วด้วย `net.devices.mac` (กรณีลงทะเบียนมือไว้ก่อน)
- ของเดิม: อัปเดต hostname, IP, firmware, model, managed_by เมื่อค่าต่างเท่านั้น — **ไม่ย้ายชั้น/ห้องที่คนกำหนดแล้ว**
- `sync.issues` (เปิดครั้งเดียวต่อ MAC, ปิดเองเมื่อหาย):
  - `unplaced_ap` — ชื่อไม่บอกชั้น (= รายการให้คนเติม) วิธีแก้ที่แนะนำ: ตั้งชื่อใน UniFi ตามรูปแบบข้างบน
  - `ip_conflict` — IP ซ้ำกับอุปกรณ์อื่นในทะเบียน (ไม่ใส่ IP ให้ AP นั้น)
  - `missing_in_controller` — AP ที่เคยนำเข้าแต่ไม่อยู่ใน UniFi แล้ว (ไม่ลบเอง)
- TLS: controller ใช้ใบรับรองที่ออกเอง → pin ใบรับรองด้วย `UNIFI_CA_FILE` (ตรวจใบรับรอง ข้ามแค่ชื่อ host); `UNIFI_TLS_INSECURE=true` ใช้ทดสอบเท่านั้น; ไม่ตั้งทั้งคู่ → งานปิดพร้อมคำเตือน
- env (worker เท่านั้น): `UNIFI_URL`, `UNIFI_USERNAME`, `UNIFI_PASSWORD`, `UNIFI_SITE`, `UNIFI_CA_FILE` (ใน container: `/run/noc-certs/…` = `/opt/sbc-noc/certs` บนเครื่อง, read-only)

ข้อมูลจริง 2026-10-03: AP 80 ตัว (online 78), รุ่น U7LR, U7MSH

- อ่านชั้นได้ ~41 ตัว: 8SFL2..8 (28), A6-1/2, AF2-1201, BFL3/5/6, BF5-2
- ชื่อไม่บอกตำแหน่ง ~39 ตัว: `AC LR` ×15, `AC Mesh` ×12, `Canteen AC LR`, `ITB AC LRA`, `AC LRA`, `UAP-AC-7AP1F/2F/4F/5F`, `UAP-AC-LRA1/8/9/12/13/15/16` → ต้องตั้งชื่อใหม่ใน UniFi หรือให้ผู้ใช้บอกตำแหน่ง

ทดสอบ (PostgreSQL 16 + UniFi จำลอง): วางชั้นถูก, code ชนกับ `ap-ba-2-1` ที่ลบแล้ว → `ap-ba-2-1-0001`, รอบสองไม่เขียนอะไร (audit ไม่เพิ่ม), ชั้นที่คนแก้ไม่ถูกย้าย, เปลี่ยนชื่อแล้ว issue ปิดเอง, AP หายขึ้น `missing_in_controller`
