# M09 — worker + คิวงาน

ตาม modules-by-gate-v2: `apps/worker` บน BullMQ + Redis (prefix `noc:`), ตารางเวลา, บันทึก `sync.runs`/`sync.issues`

**เสร็จเมื่อ:** งานตัวอย่างรันตามเวลา ล้มแล้วลองใหม่ มีผลใน `sync.runs`

## สิ่งที่สร้าง

| ไฟล์                                     | หน้าที่                                                                                                                             |
| ---------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `apps/worker/src/jobs/types.ts`          | รูปแบบงาน: `name`, `systemCode`, `schedule` (`every` ms หรือ cron Asia/Bangkok), `attempts`, `run(ctx)`                             |
| `apps/worker/src/runtime/runs.ts`        | บันทึกทุก attempt เป็นแถวใน `sync.runs` (`running` → `success`/`failed`, `detail.attempt`, error) และ `ctx.issue()` → `sync.issues` |
| `apps/worker/src/runtime/queue.ts`       | BullMQ queue `sync` + worker (concurrency 1) + `upsertJobScheduler` ต่องาน; ลองใหม่แบบ exponential backoff (ค่าเริ่ม 30 วินาที)     |
| `apps/worker/src/jobs/registry-stats.ts` | งานตัวอย่าง ทุก 5 นาที เก็บจำนวน LOC/อุปกรณ์/อุปกรณ์ไม่มีตำแหน่ง ลง `sync.runs.detail`                                              |
| `apps/worker/src/main.ts`                | ต่อฐาน + Redis, เริ่ม runtime, heartbeat, ปิดตัวเรียบร้อยเมื่อได้ SIGTERM                                                           |

- key ของ BullMQ อยู่ใต้ `<REDIS_PREFIX>bull:` เช่น `noc:dev:bull:sync:*` บน `sbc-redis` (ไม่ชนกับระบบอื่น)
- งานจริงของ M05 (SBC ASSET), M06 (controller), M08 (tag Zabbix) เพิ่มเป็น `JobDefinition` ใหม่ใน `jobs/`

## วิธีทดสอบ

```bash
TEST_DATABASE_URL=postgres://... TEST_REDIS_URL=redis://... pnpm turbo run test --filter=@sbc-noc/worker
```

การทดสอบบน PostgreSQL 16 + Redis จริง (CI job `db-integration`): งานตามเวลารันซ้ำ ≥ 2 ครั้งและบันทึก `success`; งานที่ล้มครั้งแรกถูกลองใหม่ — `sync.runs` มี `failed` (attempt 1, error) แล้ว `success` (attempt 2); `sync.issues` ได้แถวจากงาน; key อยู่ใต้ prefix

บน sbc-ubuntu (dev):

```bash
docker logs --tail 5 sbc-noc-dev-worker      # scheduled registry-stats ... / job registry-stats done
docker exec sbc-noc-dev-db psql -U sbc_noc -d sbc_noc -c \
  "SELECT id, job, status, started_at, detail FROM sync.runs ORDER BY id DESC LIMIT 3"
```
