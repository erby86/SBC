# M02 — dev stack (compose + Dockerfile)

## หน้าที่

ให้ sbc-noc รันบน sbc-ubuntu ได้จริงในโหมด dev: ฐานข้อมูลของตัวเอง ใช้ Redis ร่วม (`sbc-redis`) และ container ของ api / worker / web — ยังไม่มี schema (M03) และยังไม่ใช้ registry (M17)

## สิ่งที่สร้าง

- `packages/shared/src/env.ts` — `serverEnvSchema` + `parseEnv()` ตรวจ env ตอนเริ่ม; แจ้งชื่อตัวแปรที่ผิดโดยไม่พิมพ์ค่า
- `packages/db` — `createDbPool()`, `pingDatabase()` (pg)
- `apps/api` — `GET /health/ready` ตรวจ PostgreSQL + Redis (200 / 503 พร้อมชื่อ check ที่ล้ม), ปิดตัวเรียบร้อยเมื่อได้ SIGTERM
- `apps/worker` — ต่อ Redis และเขียน `<prefix>worker:heartbeat` (TTL 90 วินาที) ทุก 30 วินาที (ADR-0010)
- `apps/web` — แสดงสถานะ API จาก `/api/health`; nginx ส่ง `/api/*` ไป api
- `apps/{api,worker,web}/Dockerfile`, `.dockerignore`
- `infra/compose/compose.dev.yml`, `infra/compose/dev.env.example`

| container            | หน้าที่                                      | network           |
| -------------------- | -------------------------------------------- | ----------------- |
| `sbc-noc-dev-db`     | PostgreSQL 18 (volume `sbc-noc-dev-db-data`) | internal          |
| `sbc-noc-dev-api`    | Fastify :3001                                | internal + shared |
| `sbc-noc-dev-worker` | heartbeat → Redis                            | internal + shared |
| `sbc-noc-dev-web`    | nginx, เปิดพอร์ต host `5190`                 | internal          |

ข้อตกลง:

- ชื่อ service ขึ้นต้น `noc-dev-` เพราะ api/worker ต่อเข้า network เดียวกับระบบอื่น ชื่อสั้นอย่าง `api` อาจชนกับ service ของ Portal
- dev ใช้ `REDIS_PREFIX=noc:dev:` เพื่อไม่ชนกับ prod (`noc:`) บน `sbc-redis`
- จำกัด CPU/RAM ทุก container

## วิธีรันในเครื่อง (ไม่ใช้ Docker)

```bash
cp .env.example .env    # ใส่ DATABASE_URL, REDIS_URL ที่ใช้ได้
pnpm --filter @sbc-noc/api dev      # อ่าน env จาก shell
pnpm --filter @sbc-noc/web dev      # /api ถูก proxy ไป localhost:3001
```

## วิธีรันบน sbc-ubuntu

```bash
# ครั้งแรก
sudo mkdir -p /opt/sbc-noc && sudo chown "$USER": /opt/sbc-noc
git clone http://git.sbc.lan/sbc/sbc-noc.git /opt/sbc-noc/src
cp /opt/sbc-noc/src/infra/compose/dev.env.example /opt/sbc-noc/dev.env
chmod 600 /opt/sbc-noc/dev.env      # แล้วกรอกค่า

# รัน / อัปเดต
cd /opt/sbc-noc/src && git pull
docker compose --env-file /opt/sbc-noc/dev.env -f infra/compose/compose.dev.yml up -d --build
```

## วิธีทดสอบ (เงื่อนไขเสร็จ)

```bash
docker compose --env-file /opt/sbc-noc/dev.env -f infra/compose/compose.dev.yml ps      # ทุกตัว running/healthy
docker exec sbc-noc-dev-api node -e "fetch('http://127.0.0.1:3001/health/ready').then(r=>r.text()).then(console.log)"
curl -s http://noc-dev.sbc.lan/api/health                                                 # {"status":"ok",...}
docker exec sbc-redis redis-cli --scan --pattern 'noc:dev:*'                              # noc:dev:worker:heartbeat
```

## ข้อจำกัด

- ยังไม่มี schema/migration (M03); ฐานว่าง
- image build บนเครื่อง ยังไม่ push registry (M17)
- `noc-dev.sbc.lan` → `sbc-npm` proxy host → `192.168.1.6:5190` (ตั้งเมื่อ 2026-10-02; DNS `*.sbc.lan` บน MikroTik ชี้ 192.168.1.6 อยู่แล้ว) — ยังเป็น http ใน LAN
- ถ้า `sbc-redis` ตั้งรหัสผ่าน ต้องใส่ใน `REDIS_URL`
