ตาม modules-by-gate-v2: compose service PostgreSQL 16, volume, network ภายใน, role `noc_migrate`/`noc_app`/`noc_read`, pg_dump รายวัน 14 วัน / รายสัปดาห์ 8 สัปดาห์, สคริปต์กู้คืน

**เสร็จเมื่อ:** ทดลองกู้คืนลงฐานทดสอบสำเร็จ; พอร์ตไม่เปิดออกนอก docker network

**ผล (2026-10-02 บน sbc-ubuntu):** ✅ `RESTORE TEST PASSED`; ✅ `docker port sbc-noc-dev-db` ว่าง; cron backup ทุกวัน 02:30 ตั้งแล้ว

### ทำเกินขอบเขต M02 (ทำไว้ก่อน ใช้ต่อในโมดูลถัดไป)

ระหว่าง M02 รอบแรกสร้าง dev stack ทั้งชุดเกินกว่าแผน: container api/worker/web, Dockerfile, `GET /health/ready`, worker heartbeat ลง Redis, `noc-dev.sbc.lan` ผ่าน NPM — ส่วนนี้เป็นของ M13/M17/M09 ตามแผน ถือเป็นงานตั้งต้นที่โมดูลเหล่านั้นจะรับไปทำต่อ (เงื่อนไขเสร็จของโมดูลนั้นยังต้องตรวจตามแผน)

- `noc-dev.sbc.lan`: access list `sbc-noc-mgmt` (192.168.1.0/24) ใน NPM; `sbc-noc-dev-web` ไม่เปิดพอร์ต host — NPM ส่งต่อไป `sbc-noc-dev-web:80` ผ่าน network ของ NPM (`SBC_PROXY_NETWORK`) จึงเลี่ยง access list ไม่ได้

## ติดตั้งบน sbc-ubuntu

```bash
sudo mkdir -p /opt/sbc-backups/sbc-noc-dev && sudo chown "$USER": /opt/sbc-backups/sbc-noc-dev
( crontab -l 2>/dev/null; echo '30 2 * * * /opt/sbc-noc/src/infra/scripts/pg-backup.sh >> /opt/sbc-backups/sbc-noc-dev/backup.log 2>&1' ) | crontab -
```
