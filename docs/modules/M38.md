# M38 — โหมดสาธิต + ชุดข้อมูลทดสอบ

ตาม modules-by-gate-v2: ย้ายสถานการณ์ตัวอย่าง 4 ชุดจากต้นแบบเป็น fixture ของเครื่องคำนวณสถานะ และเป็นโหมดสาธิตที่เปิดได้เฉพาะ dev/staging/ผู้ดูแล (ADR-0014)

**เสร็จเมื่อ:** M15 ใช้ชุดนี้ทดสอบได้ครบ; หน้าจอโหมดสาธิตมีป้ายชัด ไม่ปนข้อมูลจริง

## สิ่งที่ทำ

| ไฟล์                                         | หน้าที่                                                                                           |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| `packages/shared/src/status.ts`              | กฎสถานะจากต้นแบบ `computeStatus()` + schema input/snapshot — ใช้ร่วมกัน: M15, โหมดสาธิต, หน้าเว็บ |
| `packages/shared/src/demo/scenarios.ts`      | 4 สถานการณ์: `mixed`, `s8down`, `stale`, `normal` (เวลาเป็น "กี่นาทีก่อน" จึงเล่นซ้ำได้ทุกเวลา)   |
| `packages/shared/src/demo/topology.ts`       | ผังสำหรับสาธิต/ทดสอบ: อุปกรณ์ 49 ตัวจาก seed + AP 2 ตัวที่สถานการณ์ใช้ (ตายตัว ไม่ตามทะเบียนจริง) |
| `packages/shared/src/demo/scenarios.test.ts` | ผลที่ต้องได้ของทั้ง 4 ชุด + กฎย่อย — **M15 ต้องผ่านชุดนี้**                                       |
| `apps/api/src/routes/demo.ts`                | `GET /demo/scenarios`, `GET /demo/scenarios/:name` เปิดเมื่อ `DEMO_MODE=true` เท่านั้น            |

กฎสถานะ (ลำดับความสำคัญ): บำรุงรักษา (ตัวมันและทุกตัวข้างใต้) > ล่ม > ขาดการเชื่อมต่อจากต้นทาง (อยู่ใต้ตัวที่ล่ม) > เตือน > ปกติ

- เหตุ (incident) = ตัวที่ล่ม/เตือนจริง เรียง ล่มก่อนเตือน → ยังไม่รับเรื่องก่อน → เก่าก่อน; ตัวที่ล่มนับ `impacted` = จำนวนอุปกรณ์ข้างใต้
- ตัวที่ขาดจากต้นทางไม่เป็นเหตุแยก (ปัญหาเดียวที่ต้นเหตุ); ถ้าตัวข้างใต้ล่มเองด้วย จะเป็นเหตุของมันเอง
- ข้อมูลเก่ากว่า 2 นาที → `stale` (เงื่อนไข M15)

ผลที่ต้องได้ (ผังสาธิต 51 ตัว):

| ชุด      | ผล                                                                                                                                 |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `mixed`  | ล่ม 2 (ap-s8-6-1, nvr-i1-1 รับเรื่องแล้ว), เตือน 2 (wan1, m-a1), บำรุงรักษา 1 (sw-bb-6); ลำดับเหตุ ap-s8-6-1, nvr-i1-1, wan1, m-a1 |
| `s8down` | m-s8 ล่มเป็นเหตุเดียว impacted 4; sw-s8-a, sw-s8-b, fin, ap-s8-6-1 ขาดจากต้นทาง; ห้องคอมฯ LOC-045/049/050 ออนไลน์ 0                |
| `stale`  | เหมือน `mixed` แต่ข้อมูลเก่า 6 นาที → stale                                                                                        |
| `normal` | ปกติทั้งหมด                                                                                                                        |

## โหมดสาธิต

- api: `DEMO_MODE=true` (compose dev ตั้งไว้; prod ค่าเริ่มต้น false) → `/api/demo/*`; ทุกคำตอบมี `demo: true` และ `label: "ข้อมูลสาธิต — ไม่ใช่สถานะจริง"`, อยู่คนละ path กับข้อมูลจริง, กลุ่ม `demo` ในเอกสาร API
- ป้ายบนหน้าจอ: ทำใน M18–M20 ตอนสร้างหน้า 3D (ใช้ `label` จาก api; แถบสีเด่นตลอดเวลาที่อยู่ในโหมดสาธิต); สิทธิ์ "ผู้ดูแลเปิดได้ใน prod" รอระบบเข้าสู่ระบบ G5

**บน dev (2026-10-03):** `/api/demo/scenarios` คืนครบ 4 ชุดพร้อมป้าย; ผลแต่ละชุดตรงตารางข้างบนทุกค่า → ส่วน fixture/API เสร็จ; ป้ายบนหน้าจอยังค้าง (M18–M20)

**ป้ายบนหน้าจอ (M20, 2026-10-05):** `/?demo=<ชุด>` (ลิงก์ "โหมดสาธิต" ใน `/admin` เมื่อ `DEMO_MODE=true`) — แถบเหลือง `label` + กรอบเหลืองรอบจอตลอดเวลา, ข้อมูลจาก `/api/demo/*` อย่างเดียว ไม่เปิด WebSocket จริง; หน้าจริงไม่มีตัวเลือกสถานการณ์ — ดู `docs/modules/M20.md`
