# M05 — ซิงก์ LOC จาก SBC ASSET

ตาม modules-by-gate-v2: งานอ่าน LOC และจำนวนเครื่องห้องคอมฯ (อ่านอย่างเดียว) → `core.locations`, `core.location_metrics`

**เสร็จเมื่อ:** ห้องใหม่ใน SBC ASSET เข้าฐานภายในรอบซิงก์; ข้อมูลขัดแย้งเปิด `sync.issues` ไม่เขียนทับเอง

## แหล่งข้อมูล

- SBC ASSET = Google Sheet `SBC_ASSET_Field_Survey_v9.2.0_Review_Workflow_RC`; รายการห้องอยู่แท็บ `08_ควบคุมการปิดพื้นที่`
- แท็บนี้มีชื่อทีมสำรวจ/ผู้ตรวจ จึงไม่แชร์ทั้งไฟล์: ผู้ใช้สร้างแท็บ `NOC_LOC_Export` (สูตร FILTER ดึงเฉพาะ building, floor, room, loc, registry, found) แล้ว **เผยแพร่ทางเว็บเฉพาะแท็บนี้เป็น CSV** (2026-10-03)
- worker อ่านลิงก์จาก `SBC_ASSET_CSV_URL` (ใน `dev.env`) — ไม่ต้องมีบัญชี Google; ลิงก์เปลี่ยนได้ด้วยการยกเลิกแล้วเผยแพร่ใหม่
- ข้อมูล ณ 2026-10-03: 172 แถว = LOC-001..186 ที่ใช้อยู่ 168 + SPORT-01..04 (เลข LOC ว่าง 18 เลข เช่น 025, 072–085) — ตรงกับ seed M04

## งาน `asset-locs` (ทุกชั่วโมง, system `sbc_asset`, actor `worker:asset-locs`)

| ไฟล์                                      | หน้าที่                                                     |
| ----------------------------------------- | ----------------------------------------------------------- |
| `apps/worker/src/connectors/sbc-asset.ts` | ดึง CSV, ตรวจหัวคอลัมน์ (ได้หน้า login แทน CSV → ล้ม)       |
| `apps/worker/src/jobs/asset-locs.ts`      | เทียบกับ `core.locations` แล้วเพิ่ม/เปิด issue/อัปเดตตัวเลข |

กติกา:

- จับคู่ด้วย `loc_code`; SPORT-xx จับคู่ด้วย `attributes.legacy_code` (ADR-0001, LOC-188..191)
- อาคารจับคู่ด้วย `core.buildings.asset_name` ("อาคาร 8 เซียน" → s8); ชั้นจาก "▶ ชั้น N"
- LOC ใหม่ (เลข < 187) → สร้างห้องบนชั้นนั้น `owner_system = sbc_asset`; รหัสที่ไม่ใช่ LOC → ออกเลขใหม่จากฐาน + เก็บ legacy_code
- LOC ≥ 187 ที่ฐานไม่ได้ออก → `loc_conflict` (SBC ASSET ต้องขอเลขจาก NOC — ADR-0001)
- ห้องที่มีแล้วแต่ อาคาร/ชั้น/ชื่อ ต่าง → `loc_conflict` **ไม่เขียนทับ**
- ห้องของ sbc_asset ที่หายจาก SBC ASSET → `loc_missing` (ไม่ลบ)
- `registry_pc_count` ใน `core.location_metrics` ตาม SBC ASSET (เปลี่ยนเมื่อค่าต่างเท่านั้น)
- issue เปิดครั้งเดียวต่อ (kind, LOC) ปิดเองเมื่อแก้แล้ว
- กันพลาด: CSV มีแถวน้อยกว่าครึ่งของห้องที่มาจาก SBC ASSET → งานล้ม (ไม่ประกาศว่าห้องหายทั้งหมด)

ทดสอบ (PostgreSQL 16 + export จาก seed): ข้อมูลเท่า seed → ไม่เขียนอะไร (audit ไม่เพิ่ม); ห้องใหม่ LOC-025 เข้า, จำนวนเครื่องเปลี่ยน → อัปเดต, ชื่อเปลี่ยน/ชั้นไม่มี/เลข NOC → `loc_conflict` โดยชื่อในฐานไม่เปลี่ยน, ห้องหาย → `loc_missing`; แก้แล้ว issue ปิดเอง; export ว่าง → ล้ม

สั่งรันทันที: `docker exec sbc-noc-dev-worker node dist/run-job-cli.js asset-locs`
